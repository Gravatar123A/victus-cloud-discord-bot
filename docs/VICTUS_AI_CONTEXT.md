# Victus AI context and memory

Customer-facing ticket replies, `/ask`, bot DMs, channel AI replies, and voice-channel answers use `nvidia/nemotron-3.5-super-vl:free` through OpenRouter. The bot uses `OPENROUTER_API_KEY` when set, otherwise the existing service-role-only `private_config.openrouter_api_key`. Speech recognition and speech output use separate audio services. There is no alternate customer text model when OpenRouter is unavailable.

Before deploying the bot, apply `sql/20261018_victus_ai_context.sql` to the linked Supabase project (also added to the website repository's Supabase migrations). The three private tables hold staff knowledge, per-user conversation turns, and historical ticket backfill checkpoints. Their row policies allow only the service role. The bot must continue using `SUPABASE_SERVICE_KEY` only on the server.

The bot captures official staff replies from Discord ticket transcripts. A background worker gradually indexes older Discord and web support replies, excluding AI and system messages. Billing, account, security, partnership, premium, and other sensitive cases are excluded from shared knowledge. Customer statements alone never become guidance. Staff can add verified guidance with `/aiknowledge add note:<freeform instruction>`. Victus AI organizes the note into a searchable topic, customer question, and answer; the bot echoes its interpretation and saves the original note. Staff can inspect recent manually added entries with `/aiknowledge list`, and remove one with `/aiknowledge remove`. Only official Victus staff can run those commands. Apply `sql/20261019_staff_knowledge_raw_note.sql` before deploying this command update.

At response time, the bot retrieves relevant live public documentation and private guidance. The website support chat retrieves both web support guidance and guidance from the official Discord support guild; `DISCORD_SUPPORT_GUILD_ID` can override the current guild ID if it changes. The bot also retrieves the asking user's recent and relevant older turns. Public and private conversation memory stay separate; public channel answers cannot retrieve DM or ticket memory. Sanitized support examples from nonsensitive tickets can inform general answers. The full archive is stored in Supabase, while each model request receives a bounded selection so context usage stays predictable.

The website admin panel's **AI Knowledge** page shows all retained entries, growth, sources, categories, search, and record details. The page queries a service-role-only database function through a staff-authenticated Next.js API route; it never exposes the service key to the browser.

Run `node node_modules/typescript/bin/tsc --noEmit --incremental false` and `node --test tests/victusAiContext.test.mjs tests/staffKnowledge.test.mjs tests/discordTicketAi.test.mjs` before deployment. After applying the migration, check `/aiknowledge list`, add a small test entry, ask a matching question in a DM, then remove the test entry. Confirm a staff ticket reply is indexed and that a different user's public question cannot retrieve private conversation details.
